# FRONTEND-057: Автотесты фронтенда и проверка языков

## Зачем
Главное правило продукта: всё на выбранном языке (ka / ru / en), без смешения. В бэкенде это
проверяют тесты, во фронтенде — только TypeScript (одинаковые ключи). Если в грузинский
словарь случайно попадёт русская строка или в переводе потеряется `{n}`, никто не заметит.
Сейчас у фронтенда нет ни одного автотеста.

## Что сделать
1. Подключить **Vitest** (`npm test`, без браузера — `environment: 'node'` или `jsdom`
   только если нужно).
2. Тест словарей (`i18n/strings.ts`, `features.ts`, `conditions.ts`, `hotels.ts`):
   - в ka — грузинские буквы, **нет кириллицы**;
   - в ru — **нет грузинских букв**;
   - в en — нет ни кириллицы, ни грузинских букв;
   - одинаковые подстановки во всех трёх языках (`{n}`, `{total}`, `{price}` …);
   - исключения (названия вроде `bina.ai`, `Premium`, `SS.ge`) — коротким списком в тесте.
3. Мелкие словари внутри компонентов (например, `components/Pagination.tsx` — `ka / ru / en`
   прямо в файле): перенести в `i18n/` или экспортировать, чтобы тест проверял и их.
   Найти все: `grep -rln "ka: {" src --include=*.tsx`.
4. Несколько тестов на логику без интерфейса:
   - `lib/searchFilters.ts`: фильтры → адрес страницы → фильтры (то же самое), неизвестные
     параметры отбрасываются;
   - `lib/format.ts`: цены, даты «сегодня / вчера / N дней назад» на трёх языках;
   - `lib/listingPreview.ts` и `lib/lazyPage.ts` — если просто.
5. CI: в `.github/workflows/ci.yml`, задание «Frontend», шаг `npm test` перед `npm run build`.

Сейчас словарь чистый (проверено: смешения и потерянных `{…}` нет) — тесты должны пройти
сразу и дальше ловить ошибки в новых задачах.

## Проверка
- `npm test` — всё зелёное. Специально вписать `'Тест'` в ka-словарь → тест падает и пишет,
  какой ключ; убрать `{n}` из en-строки → падает.
- В PR зелёное задание «Frontend» с шагом `npm test`.
- `npx tsc --noEmit` и `npm run build` без ошибок.
