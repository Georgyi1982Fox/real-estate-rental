# FRONTEND-016: Выбор тарифа на странице Premium (7 или 30 дней)

## Контекст
Бэкенд (TASK-084) теперь отдаёт **два** тарифа в `GET /api/subscription` → `plans`:

```json
"plans": [
  {"id": "premium_month", "tier": "nomad", "days": 30, "price_stars": 250},
  {"id": "premium_week",  "tier": "nomad", "days": 7,  "price_stars": 100}
]
```

Сейчас `premiumPlan()` (`src/lib/premium.ts`) берёт первый — месяц, поэтому купить неделю
в Mini App нельзя. В боте обе кнопки уже есть.

## Что сделать
1. **Страница Premium** (`src/pages/PremiumPage.tsx`): две карточки или переключатель
   «7 дней — 100 ⭐» / «30 дней — 250 ⭐». Значения брать из `plans` (не хардкодить).
   По умолчанию выбран **7 дней**; у месяца подпись «выгоднее» (цена за день ниже).
2. Кнопка «Купить» / «Продлить» отправляет `POST /api/subscription/invoice` с
   `{"plan": "<id выбранного тарифа>"}` и открывает `Telegram.WebApp.openInvoice(url)`,
   как сейчас.
3. `DEFAULT_PLAN` в `src/lib/premium.ts` (для гостя без API) — оба тарифа, как выше.
4. Таблица сравнения: строка «Цена» — «100 ⭐ / 7 дней · 250 ⭐ / 30 дней».
5. Тексты на ka / ru / en в `src/i18n/strings.ts`.

## Проверка
- В Telegram на странице Premium видно два тарифа; «7 дней» открывает счёт на 100 ⭐,
  «30 дней» — на 250 ⭐.
- После оплаты недели профиль показывает «Premium до …» (+7 дней).
- Если бэкенд вернул только один тариф — показывается одна карточка без переключателя.
- `npx tsc --noEmit` и `npm run build` без ошибок.
