# TASK-102: Акт приёмки квартиры (Premium)

## Зачем
При въезде арендатор с хозяином проходят по квартире и отмечают состояние каждого пункта.
Подписанный акт защищает залог: дефекты, записанные при въезде, нельзя удержать из
депозита при выезде.

## API
| Запрос | Что делает |
|---|---|
| `GET /api/documents/acceptance/checklist` | Чек-лист на языке пользователя: 5 разделов (комнаты, кухня, ванная, электрика и отопление, мебель и техника), 27 пунктов, состояния `ok` / `defect` / `missing`. Доступен всем |
| `POST /api/documents/acceptance` | PDF акта (Premium): грузинский + русский/английский |

Тело `POST`:
| Поле | Обязательно | Что это |
|---|---|---|
| `landlord_name`, `tenant_name` | да | Имена сторон |
| `items` | да | `[{"code": "wardrobe", "status": "defect", "comment": "царапина"}]`; коды — из чек-листа, без повторов; не указанные пункты в акт не попадают |
| `address` | если нет `listing_id` с адресом | Адрес квартиры |
| `listing_id` | нет | Объявление: адрес берётся из него |
| `handover_date` | нет | Дата приёмки, по умолчанию сегодня |
| `keys` | нет | Сколько ключей передано |
| `electricity`, `gas`, `water` | нет | Показания счётчиков |
| `notes` | нет | Примечания |
| `second_language` | нет | `ru` / `en`; по умолчанию язык пользователя |
| `delivery` | нет | `chat` (по умолчанию) — PDF в чат с ботом; `file` — PDF в ответе |

Ответ `chat`: `{"sent": true, "filename": "bina-acceptance-2026-11-01.pdf"}`.
Ошибки: 402 без Premium, 422 неверные поля или нет адреса, 404 нет объявления,
502 бот не смог отправить, 503 нет `BOT_TOKEN`.

## PDF
Заголовок на двух языках, стороны, адрес и дата, таблица «Пункт / Состояние / Комментарий»
(названия на двух языках, комментарий — как ввёл пользователь), счётчики, ключи,
примечания, подписи, совет сфотографировать квартиру.

Фото в сам акт пока не вкладываются — их хранение вместе с документами будет в TASK-115.

## Код
`application/acceptance.py` (чек-лист на ka/ru/en), `infrastructure/documents/acceptance_pdf.py`,
`infrastructure/api/routes/acceptance.py`. Общая выдача PDF (чат / файл) для договора и акта —
`infrastructure/api/delivery.py`.

## Комнаты (19.10, дизайн владельца)
Чек-лист больше не раскрыт целиком: человек сам добавляет комнаты, которые есть в
квартире, и у каждой свой список пунктов. Типы комнат — `ROOMS` в
`application/acceptance.py` (прихожая, гостиная, спальня — до 6, кухня, ванная и туалет,
балкон, вся квартира); в `GET /api/documents/acceptance/checklist` — поле `rooms`
(`code`, `title`, `items`, `max_count`). Код пункта комнаты — `<комната>-<номер>:<пункт>`,
например `bedroom-2:windows`; в PDF — «Спальня 2 — Окна и подоконники» (номер — только
если таких комнат несколько). Старые коды разделов (`entrance_door`…) по-прежнему
принимаются.
