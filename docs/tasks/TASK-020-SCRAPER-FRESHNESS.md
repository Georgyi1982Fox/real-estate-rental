# TASK-020: Актуальность объявлений и экономный парсинг

## Проблемы
1. Объявление, снятое с сайта, оставалось в поиске: повторно проверялись только
   объявления без подробностей.
2. Парсер открывал страницу каждого объявления из списка, даже если оно уже есть
   в базе и не менялось, поэтому лимит (100 на сайт) расходовался на известные.
3. Если сайт сменил вёрстку и парсер ничего не нашёл, это было видно только в логах.

## Решение
- **`checked_at`** (миграция `listing_checked_at`): когда объявление последний раз
  видели на сайте. Ставится при сохранении и для всех карточек из списка
  (`ListingsRepository.mark_checked`).
- **Страница объявления только для новых и изменившихся** (`deduplicator.needs_details`):
  новое, без подробностей, было снято, другая цена или дата обновления на сайте.
  Перед парсингом база отдаёт снимок источника (`source_snapshot`).
- **Остановка на известных**: две страницы списка подряд без новых и изменившихся
  объявлений — дальше идут старые (`KNOWN_PAGES_TO_STOP`). Лимит по умолчанию
  поднят до 500 (`SCRAPE_LIMIT`), обычно парсер останавливается раньше.
- **Повторная проверка** (`backfill_details(..., recheck_before)`): после
  дозагрузки подробностей открываются объявления, которых не было в списке
  `RECHECK_DAYS` дней (по умолчанию 3), давние первыми. В архив уходит объявление,
  если сайт ответил 404/410, перенаправил со страницы объявления на другую
  (`ListingGoneError`) или отметил его неактивным (SS: `isInactiveApplication`,
  `status`; MyHome: `is_active: false`). Снятое объявление, которое снова появилось
  в списке, возвращается в поиск.
- 4xx больше не повторяются трижды (только сеть, 5xx и 429).
- `bina-scrape` пишет «ВНИМАНИЕ», если сайт не дал ни одного объявления.

## Команды
- `bina-scrape details --limit 200 --recheck-days 3` — вручную.
- `bina-scrape schedule`: `--details-limit 200 --recheck-days 3` по умолчанию.

Около 200 проверок за запуск × 4 запуска в сутки: 2–3 тысячи активных объявлений
перепроверяются примерно раз в 3 дня.
