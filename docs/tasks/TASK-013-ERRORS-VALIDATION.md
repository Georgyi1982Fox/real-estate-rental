# TASK-013: Обработка ошибок и валидация API

> В `BACKEND_ROADMAP.md` это **TASK-017 «Обработка ошибок»** и **TASK-018 «Валидация данных»**.

## Цель
Все ошибки API в одном формате, без утечки технических деталей, с номером запроса
для поиска в логах. Пользовательский текст очищается, слишком большие запросы отклоняются.

## Требования

### 1. Единый формат (`infrastructure/api/errors.py`)
```json
{"error": {"code": "not_found", "message": "Listing not found", "request_id": "3f2a…"}}
```
| Статус | `code` |
|---|---|
| 400 | `bad_request` |
| 401 | `unauthorized` |
| 403 | `forbidden` |
| 404 | `not_found` (в т. ч. неизвестный адрес) |
| 405 | `method_not_allowed` |
| 409 | `conflict` |
| 413 | `payload_too_large` |
| 422 | `validation_error` + `details: [{field, message}]`, `field` вида `query.min_price`, `body.filters.rooms` |
| 500 | `internal_error`, сообщение всегда `Internal server error` |

- `message` — короткое пояснение на английском для разработчика. Фронтенд показывает
  пользователю свои тексты по `code` или статусу (так и работает `client.ts`: `ApiError.status`).
- **500:** трассировка и детали пишутся только в лог (`structlog`, с `request_id`), клиенту — нет.

### 2. Номер запроса
- Middleware ставит `X-Request-ID` в каждый ответ (и в тело ошибки). Входящий заголовок
  принимается, если он безопасного вида (`[A-Za-z0-9._-]{8,64}`), иначе генерируется новый.
- `request_id` привязан к логам запроса (`structlog.contextvars`).
- CORS: `X-Request-ID` разрешён во входящих и доступен фронтенду (`expose_headers`).

### 3. Порядок middleware
CORS — внешний слой: CORS-заголовки есть и в ответах с ошибками (404, 413, 500), иначе
браузер показывает «ошибку CORS» вместо настоящей ошибки. Поэтому 500 формируется
в middleware `X-Request-ID`, а не в `exception_handler(Exception)` (он работает снаружи CORS).

### 4. Валидация (`infrastructure/api/validation.py`)
- Тела запросов — Pydantic-модели с ограничениями (длина названий ≤ 100, цены ≥ 0,
  комнаты 1–10, диапазоны «от ≤ до», язык из списка).
- `clean_text`: без HTML-тегов, управляющих и невидимых символов, лишних пробелов. Применяется
  к названиям сохранённых поисков. Пустое после очистки название в `POST` — собирается из
  фильтров, в `PATCH` — 422.
- Тело больше 64 КБ — 413 (по `Content-Length`).

## Тесты
`tests/unit/api/test_errors.py`: формат 401/404/405/413/422/500, `details`, `X-Request-ID`
(свой и небезопасный чужой), 500 без утечки текста исключения, CORS-заголовки в ответах
с ошибками, очистка текста и названий.
