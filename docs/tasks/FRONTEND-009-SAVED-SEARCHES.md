## Часть A. Подключить фильтры (сейчас они не работают)
Сейчас `FilterPanel` только рисует поля, а `HomePage` запрашивает `/api/listings?page=...` **без фильтров**.

1. **Фильтры хранить в адресе страницы** (`useSearchParams`):
   `?district=<uuid>&min_price=800&max_price=2000&rooms=2&page=1`.
   Тогда ссылку на поиск можно открыть и сохранить.
2. `FilterPanel` берёт значения из адреса и при изменении пишет их обратно.
   При смене любого фильтра `page` сбрасывается на 1.
3. `HomePage` добавляет фильтры в запрос:
   `/api/listings?page=1&per_page=..&district=..&min_price=..&max_price=..&rooms=..`.
   Пустые значения не отправлять. Сервер это уже умеет; `rooms=4` означает «4 и больше».
4. **`PRICE_MAX`: с 2000 поднять до 10000**, шаг 100: реальные цены в Тбилиси доходят до 9000+ ₾.
5. Кнопка **«Сбросить фильтры»**, если выбран хотя бы один фильтр.
6. Цена: задержка ~400 мс (debounce), чтобы не отправлять запрос на каждую цифру.

## Часть B. Сохранённые поиски

### API (бэкенд TASK-028)
```
GET    /api/searches            → { items: SavedSearch[] }
POST   /api/searches            тело { name?, filters, notify } → 201 SavedSearch
PATCH  /api/searches/{id}       тело { name?, notify? } → SavedSearch
DELETE /api/searches/{id}       → 204
```
Нужен заголовок `X-Telegram-Init-Data` (клиент ставит его сам). Без него ответ 401:
показать блок «Откройте в Telegram» (`OpenInTelegram`).

Типы в `src/api/types.ts`:
```ts
export interface SearchFilters {
  district?: string;   // uuid района
  min_price?: number;
  max_price?: number;
  rooms?: number;      // 4 = «4 и больше»
}

export interface SavedSearch {
  id: string;
  name: string;         // если не передать, сервер соберёт из фильтров: «Ваке, 2 комн., до 2000 ₾»
  filters: SearchFilters;
  notify: boolean;      // присылать уведомления о новых квартирах
  new_count: number;    // новых квартир с последнего просмотра
  created_at: string;
}
```

### Что сделать
1. **Клиент API** (`src/api/client.ts`): добавить `apiDelete(path)`. Ответ 204 уже обрабатывается.
2. **Хук `src/hooks/useSavedSearches.ts`**: `searches`, `loading`, `error`,
   `save(filters, name?)`, `rename(id, name)`, `toggleNotify(id)`, `remove(id)`.
   Сначала API; при 404 или ошибке сети — mock в `localStorage` (`bina:saved_searches`),
   2–3 фейковых поиска для старта.
3. **Кнопка «🔔 Сохранить поиск»** на главной рядом с фильтрами:
   - активна, только если выбран хотя бы один фильтр;
   - после сохранения: toast «Поиск сохранён, пришлём новые квартиры» и `haptic('success')`.
4. **Страница `src/pages/SavedSearchesPage.tsx`, маршрут `/searches`** (в `App.tsx`, внутри `Layout`).
   Список карточек:
   - название и фильтры словами: «Ваке · 2 комн. · 800–2000 ₾» (название района из `useDistricts`);
   - бейдж `new_count`, если больше 0: «+5 новых»;
   - переключатель «Уведомления» (компонент `Switch` уже есть);
   - нажатие на карточку ведёт на `/?district=..&min_price=..` (фильтры применяются);
   - «Переименовать» (через `Modal`) и «Удалить» (с подтверждением);
   - скелетоны при загрузке, `ErrorState` при ошибке;
   - **empty state**: «Сохраните поиск, и мы пришлём новые квартиры первыми», кнопка «К поиску».
5. **Ссылка «Сохранённые поиски»** в `ProfileMenu` (и, по желанию, в шапке).
6. **Тексты** на трёх языках (ka, ru, en) в `src/i18n/strings.ts`.
