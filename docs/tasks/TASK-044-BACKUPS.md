# TASK-044 / TASK-045: Бэкапы базы и восстановление

## Как работает
Сервис `backup` в `docker-compose.yml` (образ `pgvector/pgvector:pg16`, скрипт
`scripts/backup.sh`) запускается вместе со всем остальным (`start-bina.bat`,
`docker compose up -d`):

- при запуске и затем каждый час проверяет: если последней копии нет или ей больше
  `BACKUP_EVERY_HOURS` (24), делает новую. Компьютер выключен ночью — копия будет
  при следующем включении;
- копия — `pg_dump -Fc` в папку **`backups/`** в папке проекта (на диске компьютера, не
  внутри Docker): `bina-2026-09-29_03-00.dump`. После записи файл проверяется
  (`pg_restore --list`), недописанная копия не появится;
- копии старше `BACKUP_KEEP_DAYS` (14) удаляются.

Папка `backups/` в `.gitignore`: в GitHub не попадает (там личные данные пользователей).

## Файлы для Windows (двойной клик)
| Файл | Что делает |
|---|---|
| `backup-now.bat` | Копия прямо сейчас + список копий |
| `restore-bina.bat` | Показывает копии, спрашивает какую (Enter — последнюю), просит ввести `yes`, останавливает бота/API/парсер, восстанавливает, запускает обратно |

## Восстановление (TASK-045)
`sh /backup.sh restore latest|<файл>`:
1. Проверяет, что копия читается.
2. Сохраняет текущую базу в `backups/before-restore-….dump` (можно откатить восстановление).
3. Заменяет базу **начисто и одной транзакцией** (`DROP SCHEMA public CASCADE` + данные копии):
   при любой ошибке база остаётся как была.

Проверено на PostgreSQL 16 с pgvector: данные (грузинский, русский текст, векторы)
восстанавливаются, таблицы, созданные после копии, удаляются; битый файл отклоняется без
изменений в базе.

## Команды вручную
```
docker compose exec backup sh /backup.sh once
docker compose exec backup sh /backup.sh list
docker compose exec backup sh /backup.sh restore latest
docker compose logs backup
```

## Важно
Копии лежат на том же компьютере. Если диск сломается, пропадут и база, и копии.
Раз в неделю копируйте папку `backups` в облако (Google Drive и т.п.). На сервере
(TASK-088) копии будут дополнительно уходить во внешнее хранилище.
