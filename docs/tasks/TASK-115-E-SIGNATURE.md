# TASK-115: Электронная подпись и хранение документов

## Как это работает
1. Человек составляет договор аренды (или акт приёмки) в приложении и выбирает
   «Отправить на подпись».
2. Документ сохраняется у нас вместе с отпечатком файла (SHA-256). Бот присылает его
   создателю в чат со ссылкой.
3. Создатель открывает ссылку, нажимает «✍️ Подписать» и пересылает ту же ссылку второй
   стороне (хозяину или арендатору).
4. Вторая сторона открывает ссылку в Telegram: бот показывает файл и кнопки
   «✍️ Подписать» / «❌ Отказаться». Подписать можно в любом порядке.
5. Когда подписали оба, каждому приходит **сертификат подписи** (PDF на грузинском и его
   языке): документ, отпечаток SHA-256, кто подписал (имя и Telegram ID), когда (время
   Тбилиси).

Третий человек с этой ссылкой подписать не может. Если кто-то отказался, вторая сторона
получает сообщение, документ становится «отклонён».

## Хранение
«👤 Профиль» → «📄 Мои документы»: все свои документы (⏳ ждёт подписей, ✅ подписан,
❌ отклонён). По кнопке бот присылает документ и сертификат ещё раз. Файлы хранятся в базе
(не в открытой папке с фото), видят их только участники.

## Юридически
Это **простая электронная подпись**: стороны подтверждают согласие своим аккаунтом Telegram,
а отпечаток показывает, что файл после подписи не меняли. Для большинства договоров аренды
этого достаточно как доказательства согласия; если нужна квалифицированная подпись (ID-карта),
договор можно дополнительно подписать на бумаге или в госсервисе.

## API (для сайта, FRONTEND-042)
- `POST /api/listings/{id}/contract` и `POST /api/documents/acceptance` с
  `"delivery": "sign"` → `{document_id, invite_url, sent}`.
- `GET /api/documents` → «Мои документы»: статус, кто подписал, `invite_url` (создателю,
  пока ждёт подписей).
- `GET /api/documents/{id}/file?part=document|certificate&delivery=chat|file`.

Удаление аккаунта удаляет свои документы и подписи; выгрузка данных включает список
документов.
