# TASK-123. Скорость Mini App: быстрый запуск и мгновенное открытие квартиры

Жалоба владельца: «объявление часто открывается медленно, страницы долго грузятся».

## Что было медленно

| Причина | Насколько |
|---|---|
| Сайт через туннель работал в **режиме разработки** (`npm run dev`): ~250 отдельных несжатых файлов (≈9 МБ), и Telegram перепроверял их все при каждом открытии | первый запуск ≈10 с, повторный ≈7 с (замер с задержкой сети 150 мс, как через туннель) |
| Открытие квартиры **ждало AI-перевод** описания, если на языке зрителя его ещё не было (новые объявления до фонового перевода, сбои AI) | до 25 с на такой квартире |
| Страница квартиры показывала заглушку, пока не ответит сервер, а «Поделиться» и район запрашивались только после этого | +1 круг по сети на каждое открытие |

Сам сервер быстрый: квартира на базе из 30 000 объявлений отвечает за ~15 мс,
похожие — ~25 мс, карта — ~7 мс.

## Что сделано

1. **Собранный сайт в Docker** (сервис `web`: `frontend/Dockerfile`, `frontend/nginx.conf`).
   - nginx отдаёт готовые файлы на `127.0.0.1:5173` (туда смотрит туннель) и пересылает `/api` в `api`.
   - Файлы с хешем кэшируются навсегда, страница — `no-cache`: обновление видно сразу.
   - Адрес `api` ищется при каждом запросе, поэтому после пересборки API nginx находит его сам.
   - Сайт пересобирается вместе со всем в `update-bina.bat` (`docker compose up -d --build`).
     Окно «Bina - site» больше не нужно: скрипты сами закрывают старое окно, если оно открыто.
   - Результат: первый запуск ≈1,2 с (10 файлов, 0,3 МБ), повторный ≈0,4 с.
2. **Перевод не задерживает открытие.**
   - `GET /api/listings/{id}` больше не ждёт AI. Если текста на языке зрителя нет и AI доступен,
     в ответе `translating: true`.
   - Сам перевод — отдельный запрос `GET /api/listings/{id}/text?lang=` (прежняя логика:
     до 25 с, сохранение, повтор не раньше чем через час после сбоя). Этот запрос просмотром не считается.
   - Страница сразу показывает фото, цену и кнопки. В блоке «Описание» видно «Переводим описание…»
     (без текста на чужом языке), потом появляется перевод.
3. **Мгновенное открытие с карточки.**
   - Карточка списка запоминает свои данные (`lib/listingPreview.ts`).
   - По нажатию страница квартиры появляется сразу (≈50 мс вместо ≈210 мс + задержка туннеля),
     полный ответ сервера тихо её дополняет.
   - Запросы блоков страницы («Поделиться», район, цена) уходят одновременно, а не по очереди.

## Как проверить (владелец)

1. Обновить: `.\update-bina.bat`. Старое окно «Bina - site» закроется само.
2. Открыть бота → Mini App: стартовый экран появляется заметно быстрее, повторно — почти сразу.
3. В поиске нажать на любую карточку — квартира открывается сразу.
   У новой квартиры без перевода в «Описании» на пару секунд видно «Переводим описание…».

## Что ещё можно ускорить позже

- Фото грузятся напрямую с сайтов-источников (ss.ge, myhome.ge) в полном размере. Уменьшенные
  копии для карточек — после переезда на сервер (TASK-088).
- Список квартир на большой базе отвечает за ~0,2 с: сортировка «Топ» + свежие по всем
  подходящим объявлениям. Ускорить можно при росте базы.
