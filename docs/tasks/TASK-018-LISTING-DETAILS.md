# TASK-018: Полные данные объявлений, фильтры по ним, «новые сверху» по дате сайта

## Что было не так
- **SS.ge** разбирался только по страницам списка: описание там обрезано (или его нет), нет
  удобств, телефона, санузлов. У MyHome страница объявления открывалась, но из неё брались
  только описание, фото и имя.
- Переносы строк в описаниях склеивались в одну строку.
- «Новые сверху» = новые **для нашей базы**: старое объявление, найденное парсером сегодня,
  оказывалось выше свежего.

## Что сделано
**Парсер** открывает страницу каждого объявления на обоих сайтах и берёт всё:

| Поле | MyHome | SS.ge |
|---|---|---|
| Полное описание (с абзацами) | ✅ | ✅ + готовые описания на ka/en от самого сайта |
| Этаж / этажей в доме | ✅ | ✅ |
| Спальни | ✅ | ✅ |
| Санузлы | — (сайт отдаёт только код) | ✅ |
| Состояние (ремонт, каркас) | ✅ | ✅ |
| Удобства | ✅ | ✅ |
| Собственник или агентство | ✅ | ✅ |
| Адрес (улица, дом), координаты | ✅ | ✅ |
| Телефон | скрыт сайтом | ✅ |
| Дата публикации / обновления на сайте | ✅ | ✅ |

Удобства и состояние хранятся **кодами** (`furniture`, `newly_renovated`…), а не текстом сайта:
приложение показывает их на своём языке. Список кодов — `src/bina/application/listing_details.py`.

**Уже собранные объявления** дозаполняются постепенно: команда `bina-scrape details` (и шаг
в расписании, до 100 за запуск) открывает их страницы. Объявление, которого на сайте больше
нет (404), уходит в архив и пропадает из поиска.

**Порядок «новые сверху»**: по дате обновления на сайте (для объявлений без неё — дата
появления у нас). При поиске по тексту — самые подходящие; при выбранной сортировке — по ней.

## API
В каждом объявлении новые поля:
```json
{
  "floor": 4, "total_floors": 9, "bedrooms": 1, "bathrooms": 1,
  "condition": "newly_renovated",
  "features": ["furniture", "air_conditioning", "washing_machine"],
  "owner_type": "owner",
  "address": "ул. Мачабели 6", "latitude": 41.69, "longitude": 44.80,
  "published_at": "2026-08-31T11:54:19Z", "updated_at": "2026-09-28T06:04:32Z"
}
```
`null` — сайт не указал. `published_at` без даты сайта — дата появления у нас.

Новые фильтры `GET /api/listings`:

| Параметр | Значение |
|---|---|
| `floor_min`, `floor_max` | этаж от / до |
| `not_first_floor=true`, `not_last_floor=true` | не первый / не последний |
| `bedrooms=2` | спален от 2 |
| `bathrooms=2` | санузлов от 2 |
| `features=furniture,air_conditioning` | есть **все** перечисленные удобства |
| `condition=newly_renovated,renovated` | **любое** из состояний |
| `owner_only=true` | только собственники |
| `published_days=7` | опубликовано за последние N дней |

Неизвестный код удобства или состояния — ответ 422. Объявления, у которых сайт не указал
нужное поле (например, этаж), под такой фильтр не попадают.

Коды удобств: `furniture`, `kitchen_appliances`, `air_conditioning`, `heating`, `hot_water`,
`washing_machine`, `dishwasher`, `fridge`, `tv`, `internet`, `gas`, `elevator`, `parking`,
`balcony`, `storage`, `pool`, `pets_allowed`, `security`.
Коды состояния: `newly_renovated`, `renovated`, `needs_renovation`, `under_renovation`,
`white_frame`, `black_frame`, `green_frame`.

## Проверка
```powershell
docker compose exec scraper bina-scrape details --limit 20
```
→ `подробности: проверено 20, обновлено …, снято с сайта …, ошибок 0`. Затем в браузере
`https://bina.test-realtybot.ru/api/listings?per_page=5` — у объявлений заполнены новые поля.
